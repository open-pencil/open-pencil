# Модели и провайдеры

[ИИ-чат](./ai-chat) использует модель, которую вы подключите: [агента для программирования](./coding-agents), который у вас уже есть, API-ключ провайдера, аккаунт [OpenPencil Cloud](/cloud/ai) или собственный сервер. С API-ключом или собственным сервером запросы идут из приложения прямо к провайдеру, а агент для программирования использует своё подключение. ИИ OpenPencil Cloud работает через собственный сервис Cloud, который пересылает каждый запрос используемому провайдеру модели.

Добавьте модель в **Настройки → Модели** или доверьте это пошаговой настройке. При новой установке вход в OpenPencil Cloud с тарифом, в который входит ИИ, настраивает его сам; уже настроенная модель остаётся как есть.

Пошаговая настройка также назначает каждому виду работы модель, которую для него рекомендует провайдер, если то, что вы уже назначили, по-прежнему работает: **Дизайн-агент** ведёт чат, **Проверка** разбирает дизайн по снимкам экрана, **Быстрые задачи** выполняют мелкую работу, например дают названия чатам, а **Зрение** читает изображения. «Зрение» настраивается, только если вы скажете, что хотите работать с изображениями. Провайдер, основная модель которого не читает изображения, например DeepSeek или Z.ai, проверяет дизайн и читает изображения по вашей просьбе той своей моделью, которая это умеет, если такая у него есть. Любую из них можно поменять в разделе **Назначения** в **Настройки → Модели**.

## Провайдеры

<ModelProviders />

**OpenAI-compatible** подходит для большинства других сервисов и локальных серверов и позволяет переключаться между API Completions и Responses. **Anthropic-compatible** подходит для сервисов, которые поддерживают Messages API от Anthropic. Введите базовый URL, ключ и ID модели, которые ожидает ваш сервер.

В **OpenRouter** можно также войти в аккаунт вместо того, чтобы вставлять ключ.

**ChatGPT** использует вашу подписку ChatGPT вместо API-ключа, и его ответы расходуют лимиты подписки. Он есть только в настольном приложении. Вход открывает браузер и возвращается в приложение через `localhost:1455` — единственный адрес, который принимает OpenAI, поэтому сначала закройте запущенный `codex login`. Вход продлевается сам, а список моделей берётся из вашего аккаунта.

## В браузере и в настольном приложении

Настольное приложение может подключиться к любому провайдеру и хранит ключи в системном хранилище учётных данных. Оно также умеет то, чего не умеет браузер: работать с агентами для программирования и входить через ChatGPT.

Веб-приложение отправляет запросы из браузера, поэтому провайдер должен это разрешать (CORS). Встроенные провайдеры разрешают; для собственного сервера или другого сервиса проверьте это, прежде чем на него полагаться.

Если веб-приложение показывает **«Не удалось подключиться к этой конечной точке из браузера»**, запрос так и не получил ответа, который браузер принял бы. Либо провайдер не разрешает запросы из браузера, либо разрешает, но не указывает это разрешение в ответах с ошибкой, и тогда неверный ключ или название модели выглядят точно так же. Попробуйте те же настройки в настольном приложении: если там они работают, провайдер блокирует браузер. В разделе [Testing a Model Provider](/development/testing-model-providers) показано, как проверить провайдера самостоятельно.

## Выбрать модель

Чат работает, вызывая инструменты, поэтому модель должна поддерживать **вызов инструментов** и надёжно передавать его потоком; модели здесь различаются даже у одного провайдера. Добавьте **зрение**, чтобы чат мог смотреть на изображения и проверять свою работу.

Модели с рассуждениями могут потратить весь бюджет вывода на размышления. Если модель останавливается, ничего не сделав, увеличьте её **Максимум выходных токенов** или понизьте **Уровень рассуждений**.

Каждый шаг ответа заново отправляет разговор и описания инструментов, поэтому длинные ответы расходуют много входных токенов. **Максимум шагов на сообщение** в разделе **Чат** в **Настройки → Модели** ограничивает это для встроенного ИИ, а агенты для программирования задают свои ограничения; см. [Пока ИИ работает](./ai-chat#пока-ии-работает).

## Хранить ключи в безопасности

В браузере ключи хранятся в зашифрованном хранилище браузера, чтобы не вводить их снова; вместо этого в настройках можно хранить их только на время сеанса. Настольное приложение использует системное хранилище учётных данных. Ключ, сохранённый в браузере, всё равно могут использовать скрипты, работающие на странице, поэтому по возможности выбирайте ключи с ограниченными правами и лимитами расходов, если провайдер их предлагает.
