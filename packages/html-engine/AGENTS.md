# HTML engine

Blitz compiled to WebAssembly with a TypeScript host. The Rust crate in `crate/` captures; `src/` loads the module, answers its requests, and validates what it returns. Depends on nothing in the workspace; Core turns captures into styled documents.

- The module and its host share a raw ABI: strings and bytes cross as (pointer, length) through `alloc`/`dealloc`, and results come back as JSON through one output buffer read with `output_ptr`. Keep wasm-bindgen out: Blitz's `web-time` pulls in imports that no capture calls, and the host binds them to functions that throw with their name. Every export the host calls is listed in `EXPORTS` in `src/engine.ts`, and every JSON shape it reads has its schema in `src/schema.ts`.
- The engine fetches nothing: Blitz's requests queue in the crate, the host answers each with bytes or `fail`, and `layout` pumps until none is left. A stylesheet in `<head>` blocks rendering until it is answered, so a failed request is answered with empty bytes rather than dropped (`tests/engine.test.ts`).
- `bun run build:wasm` (`scripts/wasm.ts`) rebuilds the module only when the crate, the root `Cargo.toml` and `Cargo.lock`, or `rust-toolchain.toml` change, and writes their hash beside it; CI's `setup-bun` action caches `wasm/` by the same files, so a job compiles Rust only when they change.
- Before pushing Rust changes, run what CI runs: `bun run check:rust` (rustfmt, clippy with warnings denied for wasm32 and the host) and `bun run check:licenses` (`cargo deny`, allowlist in `deny.toml`). A dependency change regenerates `THIRD-PARTY-NOTICES.md` with `bun run generate:notices`; CI fails when it is stale.
- Blitz is pinned to a git commit in `crate/Cargo.toml`; fixes to Blitz, Stylo, Taffy, or Parley go upstream, not into a vendored copy here.
